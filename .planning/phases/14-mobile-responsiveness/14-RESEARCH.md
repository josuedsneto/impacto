## Summary

Phase 14 is a systematic layout and grid refactor. The app's core layout shell (`frontend/app/app/layout.tsx`) renders a `w-56 flex-shrink-0` aside with no responsive breakpoint — it occupies 224px of a 375px screen, leaving only ~150px for content. This must be the first task because every other page renders inside this shell.

The fix has three distinct layers: (1) the layout shell itself — convert `aside` to `hidden md:flex` + add a Sheet drawer for mobile, sharing a `NavContent` component to avoid duplication; (2) the dashboard page inline `style={{ gridTemplateColumns: ... }}` and `ToolGrid`'s `repeat(5, 1fr)` — both must become Tailwind responsive grid classes; (3) all 8 Recharts `ResponsiveContainer` instances with hardcoded `height={N}` — these need responsive height handling, and 4 pages have non-responsive `grid-cols-N` classes that break at 375px.

The Sheet component is not yet installed (`frontend/components/ui/` has no `sheet.tsx`) but its Radix UI dependency (`@radix-ui/react-dialog` v1.4.3) is already present in `node_modules`. Installing it is a single `npx shadcn add sheet` command with no new npm package required. The project uses Tailwind v4 with CSS-based config (no `tailwind.config.js`), and standard `md:` breakpoint prefix is available and already used on several pages.

**Primary recommendation:** Add Sheet drawer to layout first, then fix grids page-by-page in dependency order (dashboard → ToolGrid → pages with non-responsive grids → Recharts heights).

### Pattern 1: Desktop Aside + Mobile Sheet with Shared NavContent

**What:** Extract nav content into a shared `NavContent` component. Desktop `<aside>` uses `hidden md:flex`. Mobile gets a `<Sheet>` triggered by a hamburger button in a top header bar visible only on mobile (`flex md:hidden`).

**When to use:** Any fixed sidebar that needs to collapse on mobile.

**Key constraints for this codebase:**
- `layout.tsx` is already `"use client"` (uses `usePathname`) — `useState` for Sheet open/closed is valid here
- The `<main>` tag currently uses inline `style={{ padding: ... }}` — the conditional padding must be migrated to Tailwind responsive classes to avoid horizontal overflow caused by `40px` padding at 375px width

**Example structure:**
```tsx
// layout.tsx (simplified diff)
"use client";
import { useState } from "react";
import { Menu } from "lucide-react";
import { Sheet, SheetContent, SheetTrigger } from "@/components/ui/sheet";
import { NavContent } from "@/components/layout/NavContent";

export default function AppLayout({ children }) {
  const [open, setOpen] = useState(false);
  return (
    <div className="flex min-h-screen">
      {/* Desktop sidebar — hidden below md breakpoint */}
      <aside className="hidden md:flex w-56 flex-shrink-0 flex-col"
             style={{ background: "#111827" }}>
        <NavContent />
      </aside>

      <div className="flex flex-col flex-1 min-w-0">
        {/* Mobile-only header with hamburger */}
        <div className="flex md:hidden items-center px-4 py-3"
             style={{ background: "#111827" }}>
          <Sheet open={open} onOpenChange={setOpen}>
            <SheetTrigger asChild>
              <button aria-label="Abrir menu">
                <Menu className="text-white w-5 h-5" />
              </button>
            </SheetTrigger>
            <SheetContent side="left" className="w-56 p-0"
                          style={{ background: "#111827" }}>
              <NavContent onNavigate={() => setOpen(false)} />
            </SheetContent>
          </Sheet>
          <span className="ml-3 font-bold text-white tracking-widest text-sm">
            SUGARCANE
          </span>
        </div>

        <main className="flex-1 overflow-auto min-w-0 p-4 md:p-8"
              style={{ background: "#f4f6f9" }}>
          {children}
        </main>
      </div>
    </div>
  );
}
```

**Critical detail:** Add `min-w-0` to both the outer flex wrapper div and `<main>` — without it, flex children can overflow their parent even with `overflow-auto`.

### Pattern 4: Recharts Fixed Heights — CSS Variable Approach

**What:** 8 `ResponsiveContainer` instances use fixed `height={N}`. On mobile `width="100%"` is already correct (ResponsiveContainer reads parent width). Only height needs to be mobile-aware.

**Recommended approach:** Wrap the `ResponsiveContainer` in a div whose height is controlled by Tailwind responsive classes. This avoids JS and re-renders.

```tsx
{/* Source: Recharts docs — ResponsiveContainer reads parent dimensions */}
<div className="h-[260px] md:h-[400px]">
  <ResponsiveContainer width="100%" height="100%">
    {/* chart */}
  </ResponsiveContainer>
</div>
```

Change `height={N}` to `height="100%"` and let the wrapper div's Tailwind classes control the actual height.

### Pattern 5: Dashboard Ticker Tape — Mobile Scroll

The ticker tape (`dashboard/page.tsx:188`) already has `overflow-x-auto` and `flex-shrink-0` on children — this is correct for mobile and needs no change. It scrolls horizontally on mobile by design.

### Pattern 6: Main Padding on Dashboard

The `<main>` tag has `padding: pathname === "/app/dashboard" ? 0 : "32px 40px"`. This conditional inline padding cannot use Tailwind responsive prefixes. On mobile, `40px` horizontal padding on a 375px viewport leaves only 295px for content.

**Fix:** Move the conditional to two Tailwind classes:
```tsx
// pathname check for zero padding on dashboard stays as-is but via className
className={cn(
  "flex-1 overflow-auto min-w-0",
  pathname === "/app/dashboard" ? "" : "p-4 md:p-8 lg:p-10"
)}
style={{ background: "#f4f6f9" }}
```

### Anti-Patterns to Avoid
- **`overflow-x: hidden` on body/main:** Hides the problem but breaks `position: sticky` and `position: fixed` elements. The layout.tsx `<main>` already has `overflow-auto` — do not add `overflow-x: hidden`.
- **`style={{ width: Npx }}` on structural elements:** Inline pixel widths are invisible to Tailwind breakpoints. Only `background`, `borderColor`, and purely visual properties are acceptable as inline styles on structural components.
- **Removing the `<aside>` entirely instead of hiding it:** The Desktop sidebar must remain in the DOM (`hidden md:flex`) so desktop users still see it. `display:none` via `hidden` is correct — not `visibility:hidden` which still takes layout space.
- **`translate-x` toggle without Sheet:** Without a focus trap and scroll-lock overlay, the mobile drawer will allow keyboard users to tab to hidden sidebar links. Use shadcn Sheet which provides these via Radix Dialog.
- **Forgetting `min-w-0` on flex children:** In a `flex` container, children default `min-width: auto`, which allows them to overflow. Add `min-w-0` to both the outer `<div className="flex flex-col flex-1">` wrapper and `<main>`.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Mobile drawer/sidebar | Custom `translate-x` CSS + `useState` open/close | shadcn `Sheet` (Radix Dialog) | Focus trap, keyboard dismiss, scroll lock, overlay, ARIA attributes — all free |
| Responsive container height | `useWindowSize` hook + conditional height | Tailwind `h-[N]` classes on wrapper div | No JS, no re-render on resize, no hydration mismatch |
| Hamburger icon | Custom SVG or CSS bars | `Menu` from `lucide-react` (already installed) | Consistent with rest of the design system |

**Key insight:** The Sheet component's value is entirely in Radix Dialog's accessibility primitives (focus management, scroll lock, keyboard events). A CSS-only drawer looks the same but fails WCAG 2.1 SC 2.1.1 and fails screen reader navigation.

## Common Pitfalls

### Pitfall 1: aside Still Takes Layout Space When "Hidden"
**What goes wrong:** Developer adds `overflow-x: hidden` to `<body>` or `<main>` instead of properly hiding the sidebar. The sidebar still occupies 224px in the flex layout even when visually clipped.
**Why it happens:** `overflow-x: hidden` is the path of least resistance — it makes DevTools stop showing overflow without fixing the root cause.
**How to avoid:** Confirm `<aside>` has `hidden md:flex` class. Inspect in DevTools with mobile emulation: the aside must report `display: none` at 375px, not `display: flex` with a negative transform.
**Warning signs:** Body width > 375px in DevTools; sticky headers still shift right when drawer opens.

### Pitfall 2: Sheet Close on Navigation
**What goes wrong:** User taps a nav link in the mobile Sheet drawer — Sheet stays open while the page navigates, showing the drawer on top of the new page.
**Why it happens:** Sheet open state is in `layout.tsx` but navigation triggers do not update that state.
**How to avoid:** Pass an `onNavigate` callback to `NavContent`. Each `<Link>` in `NavContent` calls `onNavigate?.()` via an `onClick` handler — which closes the Sheet (`setOpen(false)`).
**Warning signs:** After navigating via mobile drawer, the dark overlay remains visible.

### Pitfall 3: Tailwind v4 Grid Classes With Inline Override
**What goes wrong:** Adding `className="grid-cols-1 md:grid-cols-2"` but leaving `style={{ gridTemplateColumns: "1fr 1fr" }}` — the inline style wins at all breakpoints, Tailwind classes are ignored.
**Why it happens:** Inline `style={}` has higher CSS specificity than class-based rules.
**How to avoid:** When migrating inline grid styles, remove the `style={{ gridTemplateColumns }}` entirely and rely only on Tailwind classes.
**Warning signs:** Grid stays 2-column at 375px even after adding `grid-cols-1`.

### Pitfall 4: ResponsiveContainer height="100%" With No Explicit Wrapper Height
**What goes wrong:** Setting `height="100%"` on `ResponsiveContainer` without giving the parent div a concrete height results in a 0-height chart (Recharts cannot infer height from percentage when parent has no set height).
**Why it happens:** `height="100%"` only works when the parent has an explicit height.
**How to avoid:** Always wrap `ResponsiveContainer height="100%"` in a `<div className="h-[260px] md:h-[400px]">`.
**Warning signs:** Chart disappears entirely; browser console shows Recharts warning about zero-dimension container.

### Pitfall 5: Mobile Header Creates Double Brand Bar on Desktop
**What goes wrong:** Adding a `flex md:hidden` mobile header with the brand name "SUGARCANE" means desktop users see the brand in the sidebar AND in a top bar if the responsive class isn't applied correctly.
**Why it happens:** Class typo or missing `md:hidden` causes the mobile header to render at all breakpoints.
**How to avoid:** Test at both 375px (should show header + drawer) and 1280px (should show sidebar only, no top header). Use DevTools responsive emulation for both.
**Warning signs:** On desktop, "SUGARCANE" appears twice — once in sidebar, once in a top bar.

## State of the Art

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| `style={{ gridTemplateColumns }}` | Tailwind `grid-cols-N md:grid-cols-M` | Tailwind v3+ | Responsive grids without JS or custom CSS |
| Custom drawer with `translate-x` | shadcn `Sheet` (Radix Dialog primitive) | shadcn v1+ | Free focus trap, scroll lock, overlay, ARIA |
| `height={400}` on ResponsiveContainer | Wrapper div `h-[N] md:h-[M]` + `height="100%"` | Recharts v2+ | No JS resize listener, no hydration mismatch |
| `tailwind.config.js` | Tailwind v4 CSS-first (`@import "tailwindcss"` in globals.css) | Tailwind v4 | No config file needed; breakpoints built into the framework |

**Deprecated/outdated in this project:**
- `style={{ gridTemplateColumns }}` on layout-critical grids: overrides Tailwind classes, invisible to responsive system
- `style={{ padding: "32px 40px" }}` on `<main>`: fixed pixel padding causes overflow on mobile; must use Tailwind `p-4 md:p-8`

## Open Questions

1. **Sheet overlay z-index vs fixed Recharts tooltips**
   - What we know: shadcn Sheet uses Radix Portal (appended to `<body>`) with default z-index from the shadcn theme. Recharts tooltips are positioned absolute inside the SVG.
   - What's unclear: Whether the Sheet overlay will correctly stack above any chart tooltip if a chart is visible when the drawer opens.
   - Recommendation: Test by opening the Sheet while a chart tooltip is visible. If z-index conflict: add `className="z-50"` to `SheetContent` (standard shadcn convention).

2. **Dashboard page conditional padding — SSR vs client**
   - What we know: `layout.tsx` is `"use client"` and uses `usePathname()`. The conditional padding `pathname === "/app/dashboard" ? 0 : "32px 40px"` is already client-side.
   - What's unclear: Whether migrating to `cn()` conditional Tailwind classes in the same file introduces any visual regression on the dashboard's zero-padding hero layout.
   - Recommendation: Migrate carefully; verify dashboard full-bleed header (`background: #fff; borderBottom`) still touches edges after padding migration.
