## Cross-Phase Integration

**3 critical breaks found — all in Phase 20 ATR frontend/backend contract.**

### INT-01: `/api/atr/usinas` response shape mismatch (CRITICAL — ATR-02, ATR-05)

Backend (`main.py:862`) returns: `{"usinas": [{"id": ..., "nome": ...}]}`

Frontend (`atr/page.tsx:54-58` and `AtrUsinasAdmin.tsx:64`) does:
```typescript
const data = await res.json();
setUsinas(data as Usina[]);  // ← should be (data as { usinas: Usina[] }).usinas
```

**Impact:** `usinas` state is set to an object; `.map` renders zero `<option>` elements; form submit is disabled; the entire ATR simulate flow is unreachable. Admin table also always empty.

---

### INT-02: `/api/atr/historico` missing required param + unwrap (CRITICAL — ATR-02, ATR-05)

Backend (`main.py:905`) defines `usina_id` as a required query parameter.

Frontend (`atr/page.tsx:76-85`) omits it when `selectedUsinaId` is empty string (initial state) → 422.

Additionally, backend response is `{"historico": [...]}` but frontend casts `data as HistoricoItem[]` — even successful requests render an empty historico tab.

---

### INT-03: Admin user-association path mismatch (CRITICAL — ATR-05)

Frontend (`AtrUsinasAdmin.tsx:134`) calls:
```
POST /api/admin/usinas/{usina_id}/users   ← body: { user_id }
```

Backend (`main.py:969`) defines:
```
POST /api/admin/usinas/{usina_id}/usuarios/{user_id_target}   ← path param
```

→ Always returns 404. Admin cannot associate users to usinas via UI.
